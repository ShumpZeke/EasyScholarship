★ Insight ─────────────────────────────────────

Why the vault VIBRATES before opening — feels mechanical, not soft. The vibration envelope peaks at 20% scroll then fades, so it reads as "unlocking, then commit to opening". Without it, doors swinging from rest looks magical-but-fake; with it, it feels physical.
The lock dial spins as you approach the threshold — not random rotation, it's t * 0.6 * dialBoost + progress * Math.PI * 2, where dialBoost ramps 0→1 between 10–50% scroll. So at the moment doors start opening, dial has just completed exactly one rotation. Reads as "combination input completed → unlock."
GoldParticles splits into two pools internally (ambient = 70%, burst = 30%). Burst particles are clustered near the vault and only become visible/spread after 35% scroll — they radiate outward as doors open. Same InstancedMesh draws both with one draw call.
Camera choreography is keyframe interpolation, not a single linear lerp. 4 segments × easeInOutCubic inside each = smooth between any two adjacent shots. Adding a 5th repeated keyframe at the end safeguards floating-point math at progress = 1.0 exactly.
All section content animates via Framer Motion's whileInView — fades up 24px when you scroll into view, fades out as you leave. Set viewport={{ once: false }} so it re-triggers if you scroll back up.

★ Insight ─────────────────────────────────────

Why three-stdlib instead of three/examples/jsm/... imports? Vite chokes on the raw examples folder (CJS-style, no proper exports). three-stdlib is the maintained ES-module re-pack used by drei internally. Importing DRACOLoader from three-stdlib "just works"; importing it from three/examples/jsm/loaders/DRACOLoader.js often doesn't.
Draco vs Meshopt vs KTX2 — when to use which: Draco compresses geometry (vertex positions/normals). Meshopt also compresses geometry but is usually 20–40% smaller AND decodes faster on mobile. KTX2 compresses textures (Basis Universal → GPU-native formats like ASTC/BC7). They're complementary: a typical "production realistic GLB" uses Meshopt + KTX2 together. Old pipelines used Draco + JPG textures.
Leva's role in iterating realism: Substance Painter exports baked PBR maps with specific metalness/roughness/normalScale/emissiveIntensity values, but they almost always need tweaking once lit by YOUR HDRI in YOUR scene. Without Leva: edit code → save → wait for HMR → eyeball → repeat. With Leva: drag a slider, see the change live at 60fps. 10× faster material iteration.

# Full optimization (geometry + textures)

For just KTX2 textures on an existing model:

npx gltf-transform ktx2 input.glb output.glb
For Draco (alternative to meshopt — older but more compatible):

npx gltf-transform draco input.glb output.glb
⚠️ One gotcha for KTX2 with REAL textures
--texture-compress=ktx2 worked here because there were 0 textures (no-op). When you have real textures, KTX2 compression may need KTX-Software (toktx binary) installed system-wide on Windows. If you hit an error like "toktx not found":

Grab the Windows installer: https://github.com/KhronosGroup/KTX-Software/releases
Add the install dir to your PATH
Retry
OR fall back to --texture-compress=webp which works out-of-the-box with just sharp (which got installed as part of the 150 packages just now). WebP is ~80% as efficient as KTX2 — close enough.
